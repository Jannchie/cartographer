# 0001 分层与机器检查

日期：2026-11-28　状态：已采纳

## 背景

代码库按目录划分为插件内核、生成器、聚落引擎、渲染、编辑器、界面与插件，但依赖方向没有约束，出现了反向依赖：世界生成器与聚落引擎导入纸图渲染器的等值线模块（`render/atlas/svg/contour.ts`），聚落引擎内含聚落图渲染器（`settlement/render.ts`，依赖纸图的显示列表与注记尺寸），三维场景导入界面层的键盘约定（`ui/keys.ts`）。按模块统计时，除内核外的所有目录处在同一个依赖环中。

同时，已有的确定性检查（`scripts/check-dmath.ts`）没有进入 CI，生成代码中累积了 13 处随引擎实现而变的数学写法。

## 决定

1. 采用 `docs/architecture.md` 第 1 节的分层，依赖只能指向下层。
2. 等值线的追踪与化简属于栅格几何，移入 `gen/contour.ts`；SVG 路径的序列化留在渲染层（`render/atlas/svg/path.ts`）。
3. 聚落图渲染器移入渲染层（`render/settlementMap.ts`）。
4. 三维视图的键盘约定移入渲染层（`render/keys.ts`），界面层从那里导入。
5. 生长引擎的画图入口（`settlement/grow/paint.ts`）是对外接口的组合根，需要按需启动插件，保留在原处，登记为组合根。
6. 分层、插件依赖、world 层封闭性、运行时无环、可达性由 `scripts/check-arch.ts` 检查；确定性由 `scripts/check-dmath.ts` 检查。两者进入 CI。现存的运行时环与未接入的实验代码登记为例外，只减不增。

## 后果

- 引擎层（gen、settlement）不再依赖渲染与界面，可以单独在 Worker、Node 脚本与外部项目中使用。
- 新增的越层导入在 CI 中失败，须调整代码或修改本记录与检查脚本。
- 检查基于对导入语句的文本解析，不覆盖经由全局变量或动态拼接路径的依赖。
